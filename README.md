# 巡礼手帳

> 这是使用 [Anitabi](https://anitabi.cn) 巡礼数据制作的第三方开源 Android 应用，与 Anitabi 官方没有隶属关系。

把一部或多部动画的巡礼点放到同一张地图上，选出真正想去的地方，再生成步行、骑行、驾车或公交行程。
公开稳定版 v0.2.4 不负责中国大陆与印度点位的可用性。当前源码包含尚未发布的 v0.2.5 双地图候选；在全部授权、地区数据、地图审核、许可和真实隔离门禁完成前，中国地图与路线必须保持关闭。

## 你可以做什么

- 通过 Bangumi 搜索动画，从 Anitabi 加载巡礼点与图片。
- 同时选择多部动画，把它们的巡礼点合并到一张地图中。
- 在地图或列表中逐点选择，也可以批量选择当前地图范围内的地点。
- 总行程点数没有固定的产品上限；应用会自动排序和分批规划，实际可用数量仍受设备资源、Google 单次请求技术上限和项目共享月度额度影响。
- 使用 Google 地图查看地点和路线。
- 为步行、骑行和驾车生成道路路线，并使用 Google 道路导航。
- 在支持地区按相邻地点生成公交行程，查看线路、站点、换乘、时间和步行接驳。
- 全部巡礼点位于日本时，在本机离线判定地区和访问顺序，再由用户逐段交给 Google 地图查询公交；日本行程不会调用项目 VPS 或 Routes API。
- 活跃行程中已完成点和当前目标保持锁定，后续点可以插入、删除和重排。
- 保存完成状态和导航进度；应用重启或路线暂时无法刷新时，已保存的行程不会消失。

## 第一次使用

1. 打开应用，阅读用途说明。
2. 允许定位权限；Android 13 及以上版本还会请求通知权限，用于连续导航。首次导览还会提示关闭电池优化、在支持的系统中锁定后台任务并开启悬浮窗；这些是后台稳定性建议，不会阻止完成导览。日本公交至少需要可见通知或用户授权的悬浮窗作为外部地图期间的控制入口。
3. 搜索一部或多部动画。
4. 在地图或列表中选择要去的巡礼点。
5. 选择出行方式、起点和终点规则，然后生成路线。

你不需要申请 API Key，也不需要注册邮箱账号、填写姓名或向项目付费。

## 使用前需要知道

- 地图和新路线需要网络，以及设备上可用的 Google Play 服务。
- 没有 Google Play 服务时，仍可查看已经保存的点位、顺序和进度，但没有备用地图或路线服务。
- 步行和骑行路线会显示 Google 要求的测试版提示；请始终以现场道路、交通规则和安全状况为准。
- 日本以外的公交按相邻两点逐段调用 Routes API，并在应用内显示 Google 实际提供的线路、站台和时间。
- 日本公交不调用 Routes API：应用只生成本地访问顺序和直线距离占位段，用户每次主动把一对精确端点交给 Google 地图。路线、班次、换乘和是否存在可用公交都由 Google 地图决定，应用不会读取或推断其结果。
- 公交行程不能同时包含日本点和日本以外点；这种选择会在定位或后端请求前被拦截。中国大陆和印度仍可能因 Google Routes 数据覆盖而无法生成应用内公交结果。
- “行程点数不限”表示总行程没有固定产品上限；应用仍会自动分批，道路导航每批最多交给 Google Navigation SDK 25 个目的地，并受设备资源、Google 单次请求限制和项目共享月度额度影响。
- 路线服务不设置按匿名用户计算的每日额度或突发限制；Firebase 匿名身份只用于访问鉴权。防滥用限速使用由服务器秘密生成的 HMAC-IP，项目共享月度额度仍会生效。
- 共享月度额度用完、网络中断或路线服务维护时，路线可能暂时无法刷新，但本地行程和进度会保留。

## 隐私

- 应用不要求邮箱、姓名或密码。Firebase 匿名身份只用于验证对项目路线服务的访问，不用于设置个人额度或个人突发限制。
- 规划路线时，会发送坐标、出行方式、优化目标和出发时间等完成请求所需的信息。
- Google 路线、折线、步骤、预计时间和公交详情只保存在当前运行内存中，不写入本地数据库。
- 应用的行程持久化只保存你选择的作品、巡礼点、顺序、设置、完成状态和导航状态；本机还会保存导览与遥测同意设置、公共数据缓存和 Firebase 匿名鉴权状态。应用关闭 Android 系统备份与设备迁移。
- Google Navigation SDK 会在设备上直接处理当前位置和导航交互；完整的数据流与保留规则见隐私政策。
- 当你点击“开始日本公交行程”“打开本段”或“开始下一段”，或在无线路详情中选择“在 Google 地图中查看路线”时，应用会把该段精确起终点交给手机上的 Google 地图，并预选公共交通模式。
- Firebase Analytics 和 Crashlytics 默认关闭，必须分别主动同意才会启用，也可以随时撤回。
- 项目日志不会记录 Token、原始 IP、坐标、动画名称、搜索词或路线正文。

完整说明见 [隐私政策](PRIVACY.md) 和 [安全策略](SECURITY.md)。

## 常见问题

### 为什么显示路线服务暂时不可用？

请先确认网络与 Google Play 服务正常。项目共享月度额度耗尽、HMAC-IP 防滥用限速触发或服务维护时也会暂时停止新请求；可稍后重试，已经保存的行程不会被删除。

### 为什么连续导航显示“本月共享路线额度已用尽”？

这是项目本月共享路线额度已用完，不代表手机断网，也不是某个匿名用户达到个人上限。道路导航按 Google Navigation SDK 的技术上限每批最多预留 25 个目的地；共享额度不足以覆盖当前批次时，Google 原生导航不会启动，行程和进度仍保留在本机。

### 日本公共交通如何工作？

Google 的[官方说明](https://developers.google.com/maps/faq#transit_directions_countries)指出 Routes 的公交数据不包含日本合作方。因此从 v0.2.3 起，应用会用随 APK 固定携带的 Natural Earth v5.1.1 日本边界离线检查用户选择的巡礼点：全部在日本时不请求 VPS/Routes，而是本机排序，并在用户点击后每次只向 Google 地图提交一对端点和 `travelmode=transit`。当前位置不参与地区判定；日本点与日本以外点混合时会直接拒绝。消费版 Google 地图是否能找到公交、显示哪条路线和班次，均由 Google 地图负责。

### 哪些地区仍可能没有应用内公交？

全部非日本点继续使用 Google Routes。中国大陆、印度和其他数据不足地区可能没有可用结果；应用不会把全步行结果伪装成公交。此时可以使用错误详情中的 Google 地图核对入口。

### 为什么应用显示无线路，但 Google 地图能够找到？

两者使用的数据接口和点位接入方式并不完全相同。应用会在原错误卡中显示“详细信息”；点开后可查看失败两端的名称与经纬度，并主动跳转到 Google 地图核对该段公交路线。这只用于解释和核对错误，不会静默移动巡礼点或改变应用的路线结果。

### 为什么作品或巡礼点加载失败？

Bangumi 与 Anitabi 是独立公共服务。部分网络出口可能被其防护系统拒绝；应用不会高频重试或绕过封锁，可以稍后重试，或切换 Wi-Fi 与移动数据后再试。

### 更新会丢失数据吗？

从 v0.2.3 直接覆盖安装 v0.2.4 不需要数据库迁移。不要卸载、不要清除应用数据；行程顺序、设置和导航进度会继续保留。

### 这个应用收费吗？

应用本身免费且开源。你不需要提供支付方式或购买 API Key。路线服务使用项目共享月度额度，并保留 HMAC-IP 防滥用限速，因此不能保证任何时刻都可用。
